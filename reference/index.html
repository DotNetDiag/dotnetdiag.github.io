Scenario paths

Health Checks Only

  1. Start with Getting Started for the minimal registration pattern.
  2. Continue to Package Catalog to choose the provider package you actually need.
  3. Use Project READMEs when you need provider-specific defaults, overloads, or credential examples.
  4. Open Publishers And Metrics only if this service also needs outbound telemetry or Prometheus scraping.

Add The UI

  1. Start with Getting Started if the service does not already expose a UI-compatible health endpoint.
  2. Move to HealthChecks UI Manual for dashboard setup, storage, polling, and configuration.
  3. Use the operational guides for the next concern: UI Docker image, Webhooks and failure notifications, Interface styling and branding.
  4. Use Project READMEs as appendix material when a storage provider or extension has extra setup details.

Add Kubernetes

  1. Start with Deployment And Integrations to see the full deployment surface first.
  2. Read Liveness and readiness probes if you are only exposing health endpoints to Kubernetes.
  3. Read Kubernetes operator and Automatic Kubernetes service discovery if the rollout includes HealthChecks UI inside the cluster.
  4. Return to HealthChecks UI Manual when the cluster deployment also needs UI storage, notification, or dashboard configuration details.

Notes

The generated README catalog remains available as appendix material, but the reference manual is now the primary narrative entry point for this site. Use the README appendix when you need package-level edge cases, but start from these scenario paths when you want the supported integration path.
